# ANDARIO HOSPITALITY — WEBSITE BLUEPRINT
Version: 1.0
Status: Strategic baseline for design and development
Date: 2026-09-22

## 1. Website objective

The website is the main commercial presence of Andario Hospitality.

Its purpose is not merely to present services. It must:

1. Explain the problem faced by small and medium-sized independent accommodations.
2. Position Andario as a specialized digital partner.
3. Explain the seven services clearly.
4. Demonstrate proprietary technology through Andario Booking Engine.
5. Generate qualified commercial conversations.
6. Establish trust and credibility.
7. Prepare the brand for expansion from Colombia to Latin America.
8. Support Spanish and English audiences.
9. Provide a scalable foundation for future case studies, products and services.

Primary commercial conversion:
**Solicitar diagnóstico digital**

Secondary conversion:
**Hablar con Andario**

Product conversion:
**Conocer Andario Booking Engine**

---

# 2. Target audience

Primary audience:

- Small and medium-sized independent hostels
- Small hotels
- Posadas
- Tourist apartments
- Apart-hotels
- Cabins
- Villas
- Rural accommodations
- Entrepreneurs renting accommodation by the day

The website must speak to business owners and decision makers, not primarily to technical users.

Language should be understandable to someone who knows hospitality but may not understand software, SEO or digital marketing terminology.

---

# 3. Core website narrative

The website should guide the visitor through this sequence:

**I recognize my problem**
↓
**Andario understands my reality**
↓
**Andario has a structured solution**
↓
**The services make sense**
↓
**The technology is credible**
↓

↓

# 23. Trust architecture

Trust should be built through:

- Clear company identity
- Real contact information
- Transparent scope
- No unrealistic promises
- Explanation of process
- Proprietary technology
- Security standards
- Performance standards
- Future case studies
- Testimonials when real
- Legal documentation
- Clear privacy practices

Do not use fabricated testimonials, client logos, numbers or results.

# 26. Performance architecture

The website must be designed around performance from the beginning.

Principles:

- Minimal JavaScript
- Optimized images
- Modern image formats
- Responsive image sizing
- Lazy loading where appropriate
- Efficient CSS
- Minimal third-party scripts
- Font optimization
- CDN
- Caching
- Avoid unnecessary animation libraries
- Avoid heavy video backgrounds unless justified
- Test mobile performance continuously

Visual quality must never be achieved by sacrificing core performance.

---

# 27. Security architecture at blueprint level

The public website must follow secure development principles.

Initial requirements:

- HTTPS
- Secure headers
- Form validation
- Server-side validation where forms have backend processing
- Rate limiting where appropriate
- Anti-spam protection
- Secret management
- Dependency management
- Secure analytics implementation
- Least privilege
- Logging for relevant backend actions
- Privacy-conscious data collection

The detailed controls belong in the Security Standard.

---

# 28. Accessibility

Accessibility should be included from design, not added later.

Baseline:

- semantic HTML
- keyboard navigation
- visible focus
- sufficient contrast
- descriptive labels
- alt text
- accessible forms
- error messages
- logical heading structure
- reduced-motion consideration

---

# 29. Design direction

The visual language should combine:

**Hospitality + Technology + Trust**

Characteristics:

- Modern
- Elegant but accessible
- Spacious
- Strong typography
- High-quality photography
- Restrained motion
- Clear hierarchy
- Strong CTA
- Clean cards
- Subtle gradients or visual accents only when useful
- Mobile-first

Avoid:

- Generic SaaS dashboard aesthetic
- Excessive neon
- Excessive glassmorphism
- Heavy animations
- Stock-photo overload
- Overly corporate visual language

The site should feel like:

**A technology company that understands hospitality.**
